## 🎯 Problem

Clinical trial sites generate thousands of patient visit records that must comply with strict protocol specifications. Manual review is:
- **Slow** — one monitor can review ~100 records/day; trials have 5,000+
- **Error-prone** — human reviewers miss subtle window violations and missed procedures
- **Reactive** — problems surface during FDA audits, not before they happen

High-risk sites go undetected until regulatory audits, putting trial integrity and patient safety at risk.

---

## 💡 Solution

The **Clinical Trial Risk Monitor (CTRM)** automatically:
1. Compares every patient visit record against the trial protocol
2. Detects deviations (missed procedures, late visits, prohibited medications, dosing errors)
3. Classifies each deviation as Major / Minor / Administrative (ICH E6 GCP standard)
4. Calculates a 0–100 risk score per site using a weighted formula
5. Searches similar historical deviations via ChromaDB semantic search
6. Generates CAPA-ready reports with root cause analysis via IBM watsonx.ai
7. Exposes all of the above to **IBM Bob** via 8 MCP tools

## 🤖 IBM Bob's Role

### A. Development Workflow
Bob was used throughout the development process:
- **Planning** — architecture decisions, tool API design, schema design
- **Implementation** — TypeScript MCP server, service layer, Zod schemas
- **Debugging** — diagnosing ESM import errors, MongoDB auth failures, ChromaDB healthcheck issues
- **Code review** — identifying the missing `patientId` in detectDeviations, the missing `page` param in listHighRiskSites
- **Documentation** — generating and reviewing all docs in `docs/`

### B. Runtime Integration
At runtime, Bob is the **primary user interface**:

```
1. Clinical monitor types a question in Bob chat
2. Bob selects the appropriate MCP tool (or combination)
3. Bob calls tool with validated structured parameters
4. MCP server validates input (Zod) → calls BackendClient
5. BackendClient calls Express API → service → MongoDB/Redis/ChromaDB
6. Structured JSON result returned to Bob
7. Bob presents result as natural language response
```

Bob is not a wrapper — it is load-bearing. The 8 MCP tools are the only programmatic interface between Bob and the clinical data.

## 🔧 MCP Tools (8 total)

| Tool | Purpose | Key Inputs |
|---|---|---|
| `get_patient_records` | Query patient/visit records | `siteId`, `patientId`, `visitId`, `page`, `limit` |

| `search_similar_deviations` | Semantic search via ChromaDB | `query`, `topK` |
| `generate_capa_report` | LLM CAPA report | `siteId`, `deviationIds[]` |

## ⚡ Quick Start

```bash
# 1. Clone
git clone https://github.com/23dit040/bob-ai-hackathon-team-elite.git
cd bob-ai-hackathon-team-elite

# 2. Configure environment
cp src/.env.example src/.env
# Edit src/.env — set LLM_PROVIDER=watsonx and add API keys if needed

# 3. Build MCP server (one time)
cd src/mcp-server && npm install && npm run build && cd ../..

# 4. Build backend (one time)
cd src/backend && npm install && npm run build && cd ../..

# 5. Start Redis + ChromaDB
docker compose up redis chromadb

# 6. Start backend (new terminal)
cd src/backend && npm run dev

# 7. Start frontend (new terminal)
cd src/frontend && npm install && npm run dev

# 8. Open Bob → Settings → MCP Servers → Reload
# clinical-trial-monitor should show Connected ✅
```

Full setup: [`docs/setup-guide.md`](docs/setup-guide.md)

## ⚠️ Known Limitations

- **CAPA narrative** requires a `WATSONX_API_KEY` or `OPENAI_API_KEY`. Without one (`LLM_PROVIDER=none`), stub text is returned — corrective/preventive action tables still generated deterministically.
- **Severity classifier** uses keyword heuristics for free-text input (not a fine-tuned model). ID-based classification is deterministic with confidence 1.0.
- **ChromaDB semantic search** requires ChromaDB to be running. If unavailable, `search_similar_deviations` returns an empty array gracefully.
- **Synthetic data only** — no real patient data is included. The seed generates realistic but fictional trial records.
- **Redis optional** — if Redis is unavailable, `CacheService` falls back gracefully; risk scores are recalculated on every request.
